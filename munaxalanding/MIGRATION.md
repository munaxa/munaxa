# Migration Report — Detaching the Landing Page from the Munaxa Monorepo

Date: 2026-06-11

This report documents the full dependency audit and migration that converted the landing page
from a Munaxa monorepo workspace package (`@munaxa/landing`) into a fully standalone
application (`munaxalanding`) that can live in its own Git repository and deploy independently
on Cloudflare Workers.

> Note: package names such as `@munaxa/ui` appear in this file **only as historical record**
> of what was removed. No code, config, or manifest in the project references them anymore.

## Audit findings (before migration)

| Coupling point | Where |
| -------------- | ----- |
| `import { cn } from '@munaxa/ui'` | `src/components/ui/{button,card,badge,input,label}.tsx` |
| `"@munaxa/ui": "workspace:*"` | `package.json` dependencies |
| `"@munaxa/config-eslint": "workspace:*"` | `package.json` devDependencies |
| `"@munaxa/config-tailwind": "workspace:*"` | `package.json` devDependencies |
| `"@munaxa/config-typescript": "workspace:*"` | `package.json` devDependencies |
| `"extends": "@munaxa/config-typescript/nextjs.json"` | `tsconfig.json` |
| `import next from '@munaxa/config-eslint/next.js'` | `eslint.config.mjs` |
| `import preset from '@munaxa/config-tailwind/preset'` | `tailwind.config.ts` |
| Tailwind `content` glob reaching outside the project (`../packages/ui/src/**`) | `tailwind.config.ts` |
| Monorepo-root Docker build context, workspace `--filter` builds | `Dockerfile` |
| Workspace membership (`munaxalanding` entry) | root `pnpm-workspace.yaml` |
| Shared root lockfile (no local lockfile) | root `pnpm-lock.yaml` |
| CI building the shared UI package before deploying | `.github/workflows/deploy-landing.yml` |

No source file imported from outside the project root via relative paths, and no Turborepo
config lived inside the app (root `turbo.json` tasks simply no longer apply to it).

## Changes made

### New local implementations

- `src/lib/cn.ts` — local `cn` helper (`clsx` + `tailwind-merge`), replacing the shared UI
  package import. This was the **only** symbol the app consumed from the shared UI package.
- `tailwind.config.ts` — the full Munaxa design-system preset (colors, radii, fonts, shadows,
  gradients, `tailwindcss-animate` plugin) inlined; content glob now scoped to `./src/**` only.
- `eslint.config.mjs` — self-contained flat config reproducing the shared base + Next.js
  config: `@eslint/js` recommended, `typescript-eslint` recommendedTypeChecked, Next.js
  core-web-vitals, React hooks, Prettier compatibility, and the design-token (no hardcoded
  hex colors) guardrail.
- `tsconfig.json` — standalone config merging the shared `base.json` + `nextjs.json` settings
  (strict mode, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, bundler resolution,
  Next.js plugin, `@/*` path alias).
- `pnpm-workspace.yaml` (local) — marks this directory as its own pnpm root so installs are
  isolated from any parent workspace; also approves the `esbuild`/`sharp`/`workerd` build
  scripts pnpm 10 would otherwise block.
- `.npmrc` (local) — install settings previously inherited from the monorepo root.
- `.gitignore` (local) — previously inherited from the monorepo root; required for the
  standalone repository.
- `pnpm-lock.yaml` (local) — generated by a fresh standalone install; enables
  `pnpm install --frozen-lockfile` in CI and Docker.

### Files modified

- `package.json` — renamed `@munaxa/landing` → `munaxalanding`; removed all four
  `workspace:*` dependencies; added the dependencies extracted code needs (below); added
  `packageManager: pnpm@10.33.0`.
- `src/components/ui/button.tsx`, `card.tsx`, `badge.tsx`, `input.tsx`, `label.tsx` — import
  `cn` from `@/lib/cn` instead of the shared UI package.
- `Dockerfile` — rewritten for a standalone build context (`docker build -t munaxa-landing .`
  from this directory); no workspace filters or root manifests.
- `README.md` — all monorepo-specific commands (`pnpm --filter …`) and references replaced
  with standalone equivalents.
- `REPORT.md` — historical references to the shared packages reworded.

### Monorepo-side changes (in the Munaxa repo)

- Root `pnpm-workspace.yaml` — `munaxalanding` removed from the workspace package list.
- Root `pnpm-lock.yaml` — regenerated without the landing importer.
- `.github/workflows/deploy-landing.yml` — no longer builds the shared UI package; installs
  and deploys entirely inside `munaxalanding/` against its own lockfile. (When the app moves
  to its own repository, copy this workflow and drop the `working-directory` /
  `cache-dependency-path` settings.)

## Moving to its own repository

The directory is ready to be copied as-is into a fresh repo named `munaxalanding`:

```bash
git init munaxalanding && cp -r munaxalanding/. <new-repo>/   # or git filter-repo to keep history
cd <new-repo> && pnpm install && pnpm build
```

1. Copy `.github/workflows/deploy-landing.yml` from the monorepo into the new repo's
   `.github/workflows/`, remove the `working-directory`/`cache-dependency-path` lines, and
   set the `paths` filter to the repo root (or drop it).
2. Add the five Actions secrets to the new repo: `CLOUDFLARE_API_TOKEN`,
   `CLOUDFLARE_ACCOUNT_ID`, `SUPABASE_SERVICE_ROLE_KEY`, `RESEND_API_KEY`, `EMAIL_FROM`.
3. Delete the `munaxalanding/` directory (and the deploy workflow) from the monorepo once the
   new repo is live.

## Remaining risks / manual steps

- **Cloudflare API token permissions**: the current token authenticates but lacks the scopes
  Wrangler needs (error 10000 on `workers/services`). Recreate it from the "Edit Cloudflare
  Workers" template (plus `User → Memberships → Read`) and update the GitHub secret — this
  blocks deployment regardless of the migration.
- **Design-token drift**: the Tailwind tokens are now a copy, not a shared package. If the
  Munaxa design system changes, `tailwind.config.ts` here must be updated by hand.
- **Lint/TS config drift**: same applies to the ESLint and TypeScript configs.
- **Root-repo gitignore overlap**: while the app still lives inside the monorepo, the root
  `.gitignore` also applies; the local `.gitignore` makes the directory self-sufficient once
  copied out.
- `next-env.d.ts` is gitignored (Next.js regenerates it on `dev`/`build`);
  `cloudflare-env.d.ts` stays committed on purpose so typecheck works on a fresh clone.
